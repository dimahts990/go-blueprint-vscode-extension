# Go Blueprint

Показывает Go-модуль как холст в стиле Unreal Blueprint: каждый тип и функция — карточка,
связи между ними — провода.

| Карточка | Цвет |
|---|---|
| `S` struct (поля + методы) | синий |
| `I` interface (методы интерфейса) | зелёный |
| `T` другой именованный тип (`type X int`, `type F func()`); у «enum» — его константы со значениями | фиолетовый |
| `ƒ` функция пакета | оранжевый |

| Провод | Что значит |
|---|---|
| белый ▶ | вызов (`calls`): от строки метода/функции к вызываемому |
| серый пунктир | ссылка на функцию как на значение (`go s.run`, колбэки) |
| зелёный пунктир | тип реализует интерфейс (`implements`) |
| синий | встраивание (`embeds`) |
| жёлтый | тип поля структуры (`uses`), идёт от строки поля |
| сиреневый | метод интерфейса → его реализация (`iface → impl`, по умолчанию выкл.) |

### gRPC / protobuf слой

Если в модуле есть сгенерированный gRPC-код (`*_grpc.pb.go`, `*.pb.go`), появляются ещё два вида карточек и
бирюзовые провода `gRPC / proto`:

| Карточка | Что это |
|---|---|
| `G` сервис (бирюзовая) | gRPC-сервис из `*_ServiceDesc`; строки — RPC с бейджем `stream →` / `→ stream` / `⇄ stream` |
| `P` сообщение (малиновая) | protobuf-message: номер поля, proto-имя, `repeated` / `optional` / `map` / `oneof`, тип |

Провода: метод-обработчик (например `serverAPI.StreamWinchConfig`) → `serves` → RPC → `request` (пунктир) /
`response` / `stream` → сообщения; вложенные сообщения — от строки поля; `builds` (точки) — функция, которая собирает
сообщение (`toProto`, `streamToProto`); `client` — вызов через сгенерированный клиент. Позиции сервисов, RPC, сообщений
и полей берутся из настоящих `.proto` файлов (ищутся в модуле и в репозитории вокруг него), поэтому ⓘ и двойной клик
открывают `.proto`.

Если в модуле нет сгенерированного Go-кода (например, отдельный модуль только с `.proto` файлами), сервисы, RPC и
сообщения строятся **прямо из `.proto`** — без обработчиков, потому что Go-кода, который их обслуживает, там нет.
В списке модулей такие модули помечены «только .proto». Связь «обработчик → RPC» видна в графе Go-модуля сервера.

Если gRPC не нашёлся или `.proto` лежат в другом месте — раздел **gRPC / proto** в боковой панели показывает, что найдено,
и позволяет добавить:

- **папку с `.proto`** (`goBlueprint.protoPaths`) — для позиций и исходников сервисов/RPC/сообщений;
- **пакет со сгенерированным кодом из другого модуля** (`goBlueprint.extraPackages`) — папкой или import path
  (`github.com/org/api/gen/go/...`). Модуль должен зависеть от него (go.mod / go.work).

Папка со сгенерированным кодом из модуля, от которого текущий не зависит, загружается отдельно (показывает сервисы и
сообщения, но без связей с обработчиками). Если что-то не загрузилось — причина пишется в разделе gRPC / proto.

То же через команды `Go Blueprint: Add Folder with .proto Files…` и `Add Generated gRPC Package…`.

Пакеты — рамки-«комментарии». Вход — слева, выход — справа, как в Blueprint.

## Как пользоваться

- **Иконка графа в заголовке Go-файла** (или ПКМ по `.go` в проводнике) — вкладка «Blueprint: файл.go» только с кодом
  этого файла: его типы, функции и методы. Дальше ветку разворачивают чипами (`calls →`, `uses →`, …). Вкладка одна на
  модуль: иконка в другом файле переключает её на этот файл. На плашке — «Полный граф ↗»; если ушли по связям к другому
  символу — «✕ Вернуться к файлу».
- **Иконка Go Blueprint на панели действий слева** (рядом с «Проводником», «Поиском») — полный граф модуля; если он уже
  открыт, просто переключает на его вкладку. В боковой панели — список модулей и «Граф текущего файла».
- `Go Blueprint: Show Symbol in Graph` (`⌘⌥B` / `Ctrl+Alt+B` или ПКМ в редакторе) — файловая вкладка с фокусом на
  функции/типе под курсором; «Назад» возвращает ко всему файлу.
- На холсте:
  - фон тащить — панорама; колесо мыши / pinch — зум; трекпад двумя пальцами — панорама;
  - карточку можно перетаскивать, рамку пакета — за заголовок (едет весь пакет);
  - клик — подсветить провода узла/строки; двойной клик — открыть код; двойной клик по проводу — место вызова;
  - ПКМ по карточке/строке — Focus / Callers ← / Callees → / скрыть узел / только этот пакет;
  - `/` — поиск, `F` — вписать, `Esc` — снять выделение/выйти из фокуса, `Backspace` — назад, `Enter` — фокус на выделенном.
- **ⓘ на карточке или методе** (или клавиша `I` на выделенном) — выпадающий блок с информацией о коде: объявление,
  doc-комментарий, связи (кто вызывает / что вызывает / реализует / кем реализован — кликабельно, скрытые узлы
  показываются по клику) и исходник с подсветкой. Код берётся из открытого редактора, если файл открыт.
- **Чипы внизу карточки** (`← callers 3`, `implements → 1`, `← implemented by 2`, `all +N` …) появляются, когда
  связанные блоки скрыты; клик показывает их рядом, карточка остаётся на месте. ПКМ → «Show only X» оставляет один блок,
  дальше граф можно разворачивать этими чипами. После раскрытия рядом появляется обратный чип (`− calls → 3`,
  `свернуть всё −N`): он убирает блоки, раскрытые из этой карточки, вместе с тем, что раскрывали уже они. Блоки,
  раскрытые ещё и из другой карточки, остаются.
- В режиме фокуса сверху на холсте — **плашка статуса**: на чём фокус (функция / метод / структура / интерфейс / RPC…),
  направление, глубина, сколько блоков показано и раскрыто чипами; кнопки «◀ Назад», «Свернуть раскрытое» и
  **«✕ Выйти из фокуса»** (возвращает к обычному виду в то же место и масштаб, что были до фокуса). Под плашкой —
  цепочка переходов `A › B › текущий`, по клику можно вернуться к любому шагу. Холст в фокусе обведён оранжевой рамкой.
- Режим фокуса показывает соседей выбранного символа на заданную глубину (1–8) и направление —
  удобно ходить по цепочкам вызовов через весь проект.
- **Слои (рамки пакетов)**: в заголовке рамки `▾` — свернуть слой в миниатюру (схема его карточек, счётчики, все провода
  пакета переподключаются к ней; `▸` или двойной клик — развернуть, карточки вернутся на свои места), `✕` — скрыть слой.
  Скрытые слои собираются в плашку «Скрытые слои: N» в левом верхнем углу холста — оттуда их можно вернуть.
  Скрытие действует и в режиме фокуса (ветка через скрытый слой не раскрывается, связи с ним видны чипами);
  символ в фокусе остаётся всегда. Кнопки ▾ ✕ на рамках работают при любом зуме.
  ПКМ по заголовку: «Только этот слой», «Свернуть все остальные слои». Скрытие/сворачивание не двигает остальные карточки.
- **⇲ вынести методы** (кнопка в заголовке структуры / интерфейса / типа, ПКМ или клавиша `E`) — каждый метод становится
  отдельным блоком с пометкой «метод serverAPI» и цветной полосой типа; от типа к методам — пунктир, вызовы и gRPC-связи
  подключаются к самим методам (видно, например, что `StreamObjectGauges` вызывает `build`). В карточке типа остаётся
  строка «↳ N методов вынесены». **⇱** на любом вынесенном методе или в этой строке — свернуть обратно. По умолчанию свёрнуто.
- **⇲ на строке метода** (появляется при наведении; ПКМ по строке или `E`, когда выбрана строка метода) — вынести
  в отдельный блок только этот метод. В карточке типа на его месте остаётся строка «↳ вынесен в блок» с кнопкой **⇱**,
  которая возвращает метод обратно (то же — **⇱** в заголовке вынесенного блока).
- **⇣ возвращаемый тип** (кнопка в заголовке функции / вынесенного метода или ПКМ) — под сигнатурой раскрывается каждое
  возвращаемое значение: его тип и, если это структура или интерфейс (в том числе через `*T`, `[]T`, `map[K]T`), её поля
  или методы, а для «enum» (`type Quality int` + константы этого типа) — варианты со значениями и комментариями.
  У типов из других модулей — только экспортируемые. **⇡** — скрыть. По умолчанию скрыто.
- **Расстановка сохраняется.** Карточки можно двигать как удобно: раскладка выполняется только при первом показе вида
  или по кнопке **layout**. Новые блоки (вынесенные методы, раскрытые чипами) ставятся рядом со связанными, остальные
  не двигаются; выросшие карточки раздвигают только тех, на кого наехали. Для полного графа, каждого фокуса и каждого
  режима (режим Леня, группировка по пакетам) — своя расстановка; она сохраняется и после перезапуска VS Code.
- **расчистить** (кнопка в тулбаре, ПКМ по фону или клавиша `C`) — раскладка для больших запутанных графов: провода
  привязываются к своим строкам, порядок блоков подбирается тщательнее, чтобы было меньше пересечений, а промежутки
  между колонками расширяются по числу проходящих через них проводов. Холст получается больше, зато связи читаются.
- **⬇ режим Леня** (кнопка в тулбаре или клавиша `L`) — раскладка сверху вниз: вызывающий код сверху, вызываемый ниже;
  провода выходят снизу карточки и входят сверху, распределяясь по краю. Повторное нажатие — обратно слева направо.
- Боковая панель: `‹` или `☰` — скрыть/показать, правый край — потянуть для ширины (двойной клик — сброс), `A−`/`A+` — шрифт.
- Наведите на переключатели тулбара (`calls`, `func refs`, `fields`, …) — появится описание на русском с миниатюрой-схемой.
- При сохранении `.go` файла граф пересобирается (настройка `goBlueprint.refreshOnSave`).

Если модуль большой (>250 карточек), при первом открытии показывается только пакет активного файла —
остальные включаются в списке слева.

## Статическая симуляция

Выберите функцию или строку метода и нажмите **▷ симуляция** в тулбаре, либо выберите
**▷ Симуляция** в контекстном меню. Функцию можно также выбрать внутри панели. Введите
аргументы как JSON-объект по именам параметров и нажмите **Рассчитать**. Для метода отдельно
задайте начальное состояние receiver в формате JSON; после расчёта панель покажет его состояние.
В файловом представлении список ограничен функциями и методами открытого файла. Панель показывает
имена и типы параметров и подставляет пример JSON по Go-типам; для метода объект перед точкой
в вызове заполняется отдельно. Примеры сложных структур служат для просмотра: если тип пока не
поддерживается симулятором, расчёт недоступен, а причина показана рядом с вводом.
У метода с value receiver отображается состояние копии. Кнопка
**Показать на графе** раскрывает исходящие связи; списки показывают вызывающих и возможные
исходящие вызовы, нажатие на строку находит соответствующий узел на холсте.

Список «Возможные вызовы» строится по исходникам и не является порядком выполнения.
Повторные места вызова объединены в одну строку со счётчиком; рекурсия отмечена ↻.
После успешного расчёта «Расчётный путь» показывает вызовы, проверки условий и изменения
переменных, полученные на заданных данных. Динамическая диспетчеризация, внешние функции и вызовы через значения
функций могут отсутствовать в статическом списке.

Симулятор использует ограниченную модель Go: базовые выражения с `int`, `bool`, `string`,
локальные переменные и присваивания, `if`, цикл `for` с инициализацией, условием и шагом,
`break` и `continue`. Поддерживаются методы с прямыми полями receiver типов `int`, `bool`
и `string`; каждое такое поле нужно указать в JSON. Результаты показаны массивом возвращаемых
значений.

Например, для метода

```go
type Counter struct { Value int }
func (c *Counter) Add(n int) int {
    for i := 0; i < n; i++ { c.Value++ }
    return c.Value
}
```

аргументы `{"n": 3}` и receiver `{"Value": 2}` дают результат `[5]` и состояние
receiver `{"Value": 5}`. Шаги цикла и изменения `Value` видны в расчётном пути.

Расчёт ограничен 10 000 шагами, 32 уровнями вызовов и 32-битным диапазоном целых чисел.
Срезы, карты, `range`, вложенные структуры, глобальные переменные и внешние вызовы не
моделируются. Если порядок чтения поля и вызова метода не определён, результат тоже считается
неизвестным. Другие конструкции и состояние, которое невозможно вывести из введённых данных, не поддерживаются: результат
помечается как неизвестный. Код проекта не выполняется, поэтому симуляция не обращается
к БД, сети или файловой системе.

## Как устроено

- `analyzer/` — CLI на Go (`golang.org/x/tools/go/packages` + `go/types`). Расширение собирает его
  при первом запуске в globalStorage (нужен установленный Go). Вызовы ищутся статически по AST
  с разрешением через `types.Info`, `implements` — через `types.Implements` для всех пар тип × интерфейс модуля.
- `extension.js` — запускает анализатор, держит webview, открывает исходники.
- `media/blueprint.js` — холст: раскладка ELK (сначала каждый пакет, потом пакеты между собой),
  карточки — HTML, провода — SVG-кривые Безье.

Генерированные файлы (`*.pb.go`) и тесты по умолчанию исключены — см. настройки
`goBlueprint.includeGenerated`, `goBlueprint.includeTests`.

Анализатор можно запускать отдельно:

```sh
cd analyzer && go build -o gograph . && ./gograph -dir /path/to/module > graph.json
```

## Сборка

```sh
npm install
npm run package          # → go-blueprint-0.1.0.vsix
code --install-extension go-blueprint-0.1.0.vsix
```

## Релиз

На чистой ветке `main` запустите скрипт повышения версии:

```sh
./scripts/release.sh patch          # например, 0.13.2 → 0.13.3
./scripts/release.sh minor --push   # например, 0.13.2 → 0.14.0 и push
./scripts/release.sh major --push   # например, 0.13.2 → 1.0.0 и push
```

Если тип повышения не указан, используется `patch`. Скрипт обновляет `package.json` и
`package-lock.json` и создаёт коммит. С `--push` он также отправляет `main` на `origin`;
без него выполните `git push origin main` вручную. После push GitHub Actions создаст релиз
и приложит `.vsix`, если тег новой версии ещё не существует. В VS Code Marketplace этот
workflow не публикует.
